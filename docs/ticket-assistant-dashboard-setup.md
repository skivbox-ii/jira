применением и выбор Epic/Sprint опубликованы в `skivbox-ii/jira`, ветка
`main`: код `5febb74`, закреплённый bootstrap `8ed86a9`. Полный набор
2000/2000, браузерная проверка собранных файлов 9/9, проверки закрепления
46/46. Личная локальная проверка 1440/390 px и независимое Sol 6.1 ревью
завершены; новая версия ещё не принята в Citrix. Source/runtime/CSS и

Подробности: [приёмка компактного редактора](ticket-assistant-guided-editing-acceptance-2026-10-20.md).

Предыдущая версия: код `272cff2`, bootstrap `28c846d`. В Citrix лично проверены
настройки бюджета и подготовка тестовой ошибки с живой LLM, как со всеми
каталогами, так и с явно исключёнными компонентами/версиями.
По отдельному явному разрешению пользователя пройден полный сценарий
одной вымышленной тестовой ошибки: подготовка, уточнение, проверка,
создание и сверка сохранённых полей в Jira. Другие шаблоны этим не приняты;
детали и ограничения зафиксированы в
[отчёте от 20.10](ticket-assistant-token-budget-acceptance-2026-10-20.md).

## Настройки гаджета

На отдельном дашборде добавьте тот же тип UJG-гаджета, который используется
для импортера. Старый гаджет и его настройки не заменяйте.

| Поле | Значение |
| --- | --- |
| Название | Помощник задач |
| JavaScript URLs | `https://cdn.jsdelivr.net/gh/skivbox-ii/jira@main/ujg-ticket-assistant.bootstrap.js` |
| CSS URLs | Оставить пустым |
| AMD module | `_ujgTicketAssistant` |
| HTML to append, если это поле есть | `<div class="ujg-ticket-assistant"></div>` |

Не добавляйте одновременно source bundle, runtime bundle, скрипт импортера
или preview-файлы. Bootstrap сам загружает согласованные runtime и CSS.
Отдельный `_ujgCommon.js` этому гаджету не нужен.

## Версия На Дашборде

Используется существующий механизм `ujg.dashboardReleaseRef`. Значение общее
для всех гаджетов **одного дашборда**, а не для всей Jira.

На новом дашборде без сохранённой версии bootstrap выбирает актуальный
`main`; если запись свойства не разрешена, использует полученную версию в
текущей сессии. При недоступности источника версии есть резервный commit,
закреплённый в сборке.

При копировании старого дашборда может сохраниться версия, в которой файла
помощника ещё нет. Нажмите «Обновить версию» на новом
дашборде и дождитесь полной перезагрузки. Эта команда меняет сохранённую
версию дашборда. Старый рабочий дашборд импортера обновлять для установки
отдельного помощника не требуется.

## Jira И Шаблоны

Адрес Jira, проекты, типы, пользователи и значения полей не вводятся в
JavaScript URL или HTML. Гаджет использует текущую Jira-сессию и доступные
её пользователю API. Права на просмотр проекта и создание задач остаются
правами Jira.

Пустой исполнитель в помощнике не гарантирует неназначенную задачу:
Jira может назначить исполнителя по своим настройкам при создании.
Это поведение подтверждено в тестовом сценарии; после создания проверьте
фактического исполнителя в Jira.

1. Выберите реальный проект.
2. В «Настройках» выберите профиль DEVOPS; начальный профиль универсальный.
3. Сопоставьте «Задачу», «Ошибку» и «Развёртывание» с типами выбранного
   проекта. Несколько шаблонов могут использовать один тип Jira.
4. Примените правила и привязки. Их можно редактировать и переносить через
   экспорт/импорт JSON.

Стартовые профили входят в сборку. Изменения и черновик сохраняются лично
для пользователя, проекта и origin браузера. Настройки localhost не
переносятся автоматически в Citrix, другой браузер или коллеге.
Экспорт настроек не включает ключ подключения, черновики или вложения.

## Промпт И Бюджет Токенов

В «Настройки» / «Промпт и шаблоны» можно менять общий промпт, инструкции
шаблонов, локальный бюджет контекста и резерв ответа. Начальные значения:
32768 и 4096 токенов; для входа остаётся 28672. Это настройки приложения,
а не автоматически определённая ёмкость вашей модели. Выбирайте бюджет
с учётом возможностей подключённой модели.

Счётчик перед отправкой приблизительный: токенизатор произвольной модели
неизвестен. Разбивка включает инструкции, исходный текст, поля Jira и
служебные данные. Если сервис возвращает `usage`, его фактические значения
показываются отдельно. Резерв уменьшает доступный вход локально и не
отправляется как ограничение длины ответа провайдеру.

При превышении бюджета запрос не отправляется и не обрезается. Кнопка
в предупреждении открывает настройки. Старые настройки мигрируют без
потери промптов; бюджет переносится экспортом JSON и сохраняется вместе
с персональными правилами проекта. После изменения бюджета черновик
потребует повторной проверки.

Ссылка подключения не меняется. Если осталась прежняя версия, нажмите
«Обновить версию» на отдельном дашборде помощника.

## Редактирование С Помощником

В компактной шапке находятся проект, шаблон, тип Jira и кнопки настроек,
подключения AI, токенов и полноэкранного режима. Счётчик токенов открывается
по кнопке, но превышение бюджета остаётся видимым в ответе помощника.

У поддерживаемого поля кнопка AI открывает действия «Сгенерировать»,
«Улучшить», а у текстовых полей также «Сократить». Ответ не заменяет поле:
сначала показаны текущее значение и предложение. «Применить» меняет
только выбранное поле, «Отклонить» сохраняет текущий текст. Правка исходника
или полей отменяет устаревшее предложение. Общие «Подготовить» и
«Проверить» сохраняют прежнее назначение.

Тема и описание находятся в начале редактора. Пустые необязательные поля
доступны в «Дополнительно»; заполненные, обязательные и проблемные поля
остаются видимыми. Поля, которых нет на доступном экране создания Jira,
помощник не может добавить или сделать доступными самостоятельно.

Epic и Sprint выбираются вручную по фактической схеме проекта. Для Sprint
сначала выбирается доступная Scrum-доска. Неполные результаты поиска
помечаются явно; перед проверкой и созданием выбранные связи сверяются
заново. Пользователи и числовые оценки, включая Story Points, не
генерируются моделью. Исполнитель может быть ограничен настройками профиля,
а при отсутствии явного выбора Jira применяет собственные правила назначения.

Новая форма требует отдельной приёмки на реальной Jira; результаты и
ограничения опубликованы в
[отчёте по управляемому редактированию](ticket-assistant-guided-editing-acceptance-2026-10-20.md).

## Подключение LLM

Используется тот же shared LLM client и ключ localStorage
`ujg-shared-llm-config`, что у импортера и Timesheet. Существующая
конфигурация в том же браузере и на том же Jira origin переиспользуется.
Персональные правила DEVOPS не заменяют параметры соединения.

Параметры соединения: API Base URL существующего разрешённого сервиса,
точное имя модели, API key; для сервиса с прежним протоколом также
`Legacy /completions`. Не помещайте ключ в HTML, URL гаджета, шаблоны,
репозиторий или сообщения с инструкцией.

В новом гаджете нажмите **«Подключение AI»**, заполните эти поля и нажмите
«Сохранить». Кнопка доступна до выбора проекта. Ключ вводится в поле пароля.
«Отмена» не сохраняет изменения; ошибка localStorage показывается явно.
Базовый промпт существующей общей конфигурации сохраняется без изменения.
После смены подключения текущий и другие уже открытые редактируемые
черновики необходимо проверить заново. Их текст и поля сохраняются;
блокировки завершённого или неопределённого создания не снимаются.

Эта конфигурация общая с другими виджетами на том же origin браузера.
Меняйте её только осознанно. Сохранение настроек само по себе не должно
запускать запрос к модели.

## Порядок Приёмки После Публикации

- Проверить совпадение опубликованных runtime/CSS с проверенной сборкой.
- В Citrix проверить загрузку гаджета, проектов, типов и полей без записи.
- Пользователь явно запускает «Подготовить» и «Проверить» на разрешённых
  примерах для трёх шаблонов. Заглушки не подтверждают качество живой LLM.
- Не нажимать «Создать задачу» ради проверки загрузки. Создание задачи
  является отдельным явным действием пользователя.

Текущий статус и доказательства локальных проверок:
[отчёт приёмки](ticket-assistant-acceptance-2026-10-19.md).
