## Что осталось

1. **DUE-03 не реализована:** срок Excel есть в аналитике и отдельной
   синхронизации, но `creator.storyFields` не передаёт `duedate` при
   создании новой Story. Эти сценарии нельзя считать взаимозаменяемыми.
   В бэклоге пункт по-прежнему записан как дизайн, ожидающий отдельного
   подтверждения; самопроверка не меняет его на «выполнено».
2. **Проверка компонента не едина для всех команд:** синхронизация
   сверяет реальный каталог, а первичное создание отправляет имя из
   маппинга без повторной проверки. Неизвестное имя может привести к
   отказу Jira. Предупреждение в настройках не является запретом записи.
3. **Четыре известных замечания UI открыты:** потеря поиска при конце
   загрузки, неясная актуальность сохранённого снимка после ошибки,
   прокручиваемый крестик, неверная причина пропуска пустого Jira-ключа.
   Подробные шаги: `docs/import-ui-audit-2026-09-27.md`.
4. **Данные реального журнала не полностью проверены:** EXCEL-01
   (малое число строк и пустые ответственные), REG-03 (источник модуля
   и старые неправильные соответствия), DUE-02 (исходные 39 сроков).
   Новый Excel и синтетический файл не доказывают корректность старого.
5. **Новая production-приёмка не выполнена:** по последней доступной
   проверке Citrix `Failed to reconnect`. Успешные проверки прежних
   релизов не закрывают PERF-01, EXCEL-02 и другие пункты с ожидающей
   приёмкой. Реальные записи и живой LLM не выполнялись.

`Not in catalog`; Excel содержит срок `27.09.2026`.

Результат:

```json
{"onlyLocalStubs":true,"catalogReads":0,"attemptedCreates":1,"submittedComponent":"Not in catalog","hasDueDate":false,"resultOk":true}
```

`resultOk` означает успех намеренно принимающей заглушки, не Jira.
Неизвестный компонент дошёл до границы записи; поле срока отсутствует.

`main.js:3188` (`createConfirmedRow`); настройки сохраняют маппинг в
`main.js:2827`, UI лишь предупреждает в `rendering.js:1074`.

## Где моя проверка была недостаточной

- Прошлый отчёт перечислял дефекты конкретного UI-прогона, а не все
  незакрытые требования истории. Нужно было явно напомнить DUE-03,
  EXCEL-01, REG-03 и DUE-02, а не ограничиваться числом «четыре».
- Тест `history progress preserves table, filter draft, focus and report
  calculations` (`activity-ui.test.cjs:56`) вызывает `updateProgress`,
  но не финальный `render`. По нему нельзя утверждать, что черновик
  сохраняется до самого конца. Ручной прогон обнаружил эту границу.
- Нельзя переносить проверку компонента из команды синхронизации на
  создание: это разные пути кода. Их нужно проверять отдельно.
- Синтетическая успешная загрузка ответственных/модулей не объясняет
  пустые колонки реального Excel. «Нет данных» и незавершённая диагностика
  должны оставаться такими, пока исходные значения не прочитаны.
- Нельзя считать локальную запись, успешный LLM-stub или старую приёмку
  Citrix подтверждением новой production-версии.
