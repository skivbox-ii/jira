# Локальное подключение Confluence в VDI

Это первый этап нового чата: **сервер подключения и диагностика, не готовый LLM-дашборд**.

`scripts/start-knowledge-bridge.ps1` запускается в Windows PowerShell 5.1 без Node/Python. Страница и API находятся на одном локальном адресе `http://localhost:8769/`; PowerShell обращается к Confluence. Заголовки сервера Confluence менять не требуется. Этот процесс не предоставляет доступ виджету на домене Jira: браузер нужно открыть именно на локальной странице.

## Запуск

Проверка 03.11.2026: выпуск `cc8eeb840b777b0f97af52fff3cdf90d6052e318` скачан в VDI, SHA-256 совпал, но запуск отклонён корпоративной Software Restriction Policy. До разрешения запуска поддержкой VDI локальный сервер там не работает. См. `knowledge-bridge-acceptance-2026-11-03.md`.

Скачать скрипт из закреплённого коммита репозитория `skivbox-ii/jira`, сверить SHA-256 с отчётом выпуска и запустить в отдельной PowerShell-сессии. Не использовать `iex` для непроверенного ответа сети. Не останавливать уже работающие серверы в другой вкладке ISE.

```powershell
.\start-knowledge-bridge.ps1 -ConfluenceBaseUrl 'https://confluence.example.org' -AuthMode None
```

Вместо примера указать настоящий HTTPS-адрес Confluence. Порт можно изменить через `-Port`. Остановка — Ctrl+C либо Stop в отдельной сессии ISE.

## Авторизация

- `None` проверяет доступ без учётных данных. Вход в Edge не переносится автоматически в PowerShell. Ответ страницы входа не считается успешным подключением.
- `Windows` явно использует текущие Windows credentials. Работает только если Confluence/прокси поддерживают соответствующую авторизацию; наличие SSO в браузере этого не доказывает.
- `Token` запрашивает персональный маркер через скрытый ввод PowerShell. Маркер остаётся в памяти процесса и не передаётся локальной HTML-странице. Вводить его должен пользователь; не присылать ключ агенту и не вставлять в командную строку.

Токен Confluence наследует права владельца. Сервер ограничивает запросы чтением текущего пользователя, поиском заголовков и чтением конкретной страницы. Это не универсальный HTTP-прокси.

## Проверка

Открыть локальную страницу, проверить сервер, затем текущего пользователя Confluence. Только после подтверждения JSON и пользователя выполнить поиск `DevOps` и прочитать найденную страницу. В этой версии нет вызовов LLM, записи в Jira или Confluence. Локальные тесты не заменяют эту проверку.

```powershell
powershell -NoProfile -File .\tests\knowledge-bridge.tests.ps1
```

Скрипт не меняет ExecutionPolicy, доверие TLS, firewall или URL ACL. Если корпоративная политика запрещает запуск или локальный listener, он должен сообщить ошибку; обход политик автоматически не выполняется. Страница доступна только на loopback; API защищён случайным ключом сессии и проверкой Origin/Host. Не включать наружный bind или wildcard CORS.

## Дальнейшая интеграция

После реальной проверки авторизации подключить этот транспорт к отдельному интерфейсу Pico, затем отдельно добавить разрешённый доступ к Jira и существующему LLM. Запуск сервера сам по себе не означает готовность чата и доступ к этим двум системам.
