# Одна JS-сборка импортера

По прямому запросу пользователя от 20.11.2026 SheetJS 0.18.5, JSZip 3.10.1
и Mermaid 11.15.0 включены в JS импортера. Отдельных запросов за этими
библиотеками при чтении Excel, скачивании обновлённого файла и открытии
схем больше нет. Версии сохранены, исходные дистрибутивы и лицензии находятся
в `vendor/` и `docs/licenses/`; контрольные суммы — в `vendor/README.md`.

## Реализация

Сборщик создаёт приватные AMD-модули. Загрузчик Excel, парсер, ZIP-патчер
и рендерер используют их напрямую. Библиотеки не подменяют глобальные
объекты Jira и не используют её одноимённые AMD-модули.

Публичный JS и runtime — два существующих варианта входа в один и тот же
импортер; каждый содержит зависимости целиком. Это не обещание одного
HTTP-запроса на всю страницу Jira: штатный bootstrap и CSS сохраняются.
Размер JS вырос примерно с 1,15 до 5,44 МБ до транспортного сжатия.
Взамен Excel и схемам не нужны дополнительные загрузки скриптов.

Независимое ревью Sol 6.1 выявило автозапуск Mermaid по событию `load`:
по умолчанию библиотека сканирует чужие `.mermaid` на странице. Дефект
воспроизведён на обоих вариантах сборки и исправлен: `startOnLoad:false`
устанавливается до выдачи приватного модуля. Регрессионный тест вызывает
настоящий обработчик библиотеки; браузерный сценарий дополнительно
проверяет, что посторонняя схема остаётся неизменной. Повторное независимое
ревью: открытых замечаний нет.

## Локальные проверки

- 1371/1371 профильных проверок импортера, bootstrap и standalone-экспорта.
  Включены чтение реальных XLSX, сохранение исходных ячеек и запись ключа/
  статуса через встроенный JSZip в обоих опубликованных вариантах JS;
  даты и системы 1900/1904, а также разные часовые пояса.
- В расширенной группе 6 интеграционных проверок прошли: фикстуры нагрузки,
  дневная история, запуск заполненного реестра, предварительная таблица
  сроков с записью только выбранной строки на заглушке. Одна проверка
  компонентов не прошла; причина и отдельная диагностика описаны ниже.
- Chromium, 1440×900 и 390×900: чтение тестовой книги, скачивание и обратное
  чтение обновлённого XLSX, открытие реальной Mermaid-схемы. Любые внешние
  запросы и отдельные библиотечные скрипты запрещены тестом. Дополнительных
  запросов за библиотеками — 0, ошибок страницы — 0, изменений Jira — 0.
- Повторён сценарий маппинга 16.11 на широком и узком экране: окно появляется
  каждый раз, ручные назначения сохраняются, отмена не записывает черновик,
  лист/заголовок определяются, файл только с номерами импортируется.
- Личная проверка в локальном браузере: Excel-реестр заполнен, описание
  связанной задачи открывается и содержит отрисованную схему. Снимки обоих
  размеров из браузерного сценария просмотрены отдельно.
- Исходники проверены на пробельные ошибки; upstream-дистрибутивы сохранены
  побайтово, включая пробелы в шаблонах Mermaid. Их SHA-256 не изменились.

Ограничение расширенного прогона: неизменённый JSDOM-тест предпросмотра
компонентов превышает ожидание готовности формы. Это воспроизведено и на
исходном `e287c34` с прежними HTML/JS/CSS и отдельными библиотеками: 84,8 с
против 85,7–88,5 с на новой сборке. На исходном варианте 82,9 с заняли
расчёты стилей. В диагностическом запуске текущей сборки без расчёта ширин
отсоединённых элементов таблицы все прежние функциональные проверки
прошли за 11,4 с; лимиты ожидания и проверки не менялись. Этот адаптер
не включён в репозиторий, падение исходного JSDOM-теста не считается
успешной проверкой и не скрывается общим зелёным счётчиком.

Повторяемые сценарии: `tests/excel-story-importer-bundled-deps.test.js`,
`tests/browser/import-bundled-deps-acceptance.cjs`,
`tests/browser/import-file-mapping-acceptance.cjs`.

## Приёмка в Citrix

Не выполнена агентом; остаётся за пользователем. Обновить версию виджета,
открыть свой Excel, применить соответствия и скачать обновлённый файл.
При наличии схемы открыть описание задачи. В Network не должно быть
отдельных `xlsx.full.min.js`, `jszip.min.js` или `mermaid.min.js`.
Создавать или изменять задачи Jira для этой проверки не требуется.
