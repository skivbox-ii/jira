# Проверка направления связей при создании

Дата: 24.09.2026. Проверка кода и локальных тестов; рабочие тикеты Jira не создавались и не изменялись.

## Результат

Подтверждена ошибка общего выбора направления связи. `createRow` (новая история с задачами) и `createAdditionalTasks` (новые задачи к существующей истории) используют один `resolveChildLinkType` и `childLinkPayload`.

До исправления совпадение имени типа с настроенным `Child` всегда выбирало `parentOutward: true`, игнорируя описания направлений. Для типов с другим именем описания интерпретировались наоборот. Поэтому при `outward: is parent of`, `inward: is child of` существующая история могла становиться дочерней для новой задачи. Это ошибка общего обработчика, а не отдельной ветки дозаведения.

## Правило

Jira отображает связь с другой задачей по метке соответствующего конца связи:

| Описания типа | POST inwardIssue | POST outwardIssue |
| --- | --- | --- |
| outward = is parent of, inward = is child of | исходная история | новая QA/BE |
| outward = is child of, inward = is parent of | новая QA/BE | исходная история |

Приоритет настроенного имени типа сохранён, направление теперь определяется его описаниями. Проверяются также `parent`, `has child`, `has children`. Если метаданные недоступны, сохраняется прежнее резервное направление `Child`; универсально доказать его корректность без настроек конкретной Jira нельзя.

Источники: [модель связей Atlassian](https://developer.atlassian.com/cloud/jira/platform/issue-linking-model/), [создание связей Cloud и Data Center](https://support.atlassian.com/jira/kb/how-to-use-rest-api-to-add-issue-links-in-jira-issues/).

## Проверка

- Регрессионные тесты воспроизвели неправильное направление до исправления.
- Матрица проверяет первичное создание и дозаведение, настроенное и нестандартное имя типа, обе ориентации, четыре варианта родительской метки.
- После исправления 152 теста creator/enrichment/main проходят.
- Существующие производственные связи автоматически не исправляются. Для оценки исторических последствий нужны конкретные ключи задач и отдельная проверка их связей в Jira.
