# DUE-03: Срок Новой Истории, 27.09.2026

## Объём

Согласованный пункт продолжения 27.09: при создании новой исходной Story
передавать подтверждённый срок Excel в Jira `fields.duedate`. Отдельная
синхронизация DUE-04, существующие истории, дозаведение детей и сроки
дочерних задач не меняются.

Используется существующий `deadlines.resolve` с фактическим `columnMap`.
В форме отдельный черновик даты, исходные значения и причина проблемы.
Непустой ошибочный/конфликтный срок требует исправления либо явной
галочки «Не указывать срок». Отсутствующий срок не выдумывается.
Отмена и правка только поля Due date не меняют исходные ячейки Excel.

## Защита Записи

`creator` повторно проверяет дату до чтения каталога компонентов и
любого создания. Ручное значение строго DD.MM.YYYY или YYYY-MM-DD,
с проверкой календаря. В Jira отправляется ISO-дата. При отказе Due date
ошибка остаётся видимой; повтор без срока не выполняется. Существующий
повтор без недоступного Epic Link сохраняет срок и проверенный ID компонента.
