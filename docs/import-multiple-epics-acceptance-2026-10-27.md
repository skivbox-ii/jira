## Поведение

Один список «Эпики: N» с поиском и галочками позволяет выбрать несколько
эпиков текущего проекта. «ОК» применяет набор; отмена, Escape и клик
снаружи не меняют действующий выбор. Пустой набор означает все истории
проекта. Выбор сохраняется отдельно для пользователя и проекта;
прежний одиночный ключ читается без потери настроек таблицы.

Поиск объединяет эпики через Epic Link IN. Лёгкие страницы 50/25,
последовательная догрузка истории и ограничения полноты сохранены.
Связанная с двумя замечаниями задача читается один раз. Полный набор
учитывается в Динамике, экспорте и AI-контексте, а также в защите от
поздних ответов. Порядок выбора не меняет область данных.

Форма создания Story по-прежнему содержит ровно один Epic. При нескольких
эпиках просмотра она не выбирает первый автоматически; показывает
пояснение и оставляет явный выбор одного или «Без Epic».

## Воспроизведение и проверки

- Исходная сборка не поддерживала множественный список: новая браузерная
  приёмка завершилась RED на открытии списка «Эпики».
- Стенд `import-multiple-epics-fixture.js`: 69 историй в трёх эпиках,
  по 23 на эпик, общая дочерняя задача двух историй. Транспорт учитывает
  фактический JQL, fields и expand. Выбор двух даёт ровно 46 историй,
  третий эпик исключён; история общей задачи читается один раз.
- Личная проверка IAB обнаружила конфликт глобального стиля input:
  checkbox занимал 369 px, текст сжимался до 9 px, строка вырастала
  до 351 px. В браузерную приёмку добавлена проверка реальных размеров
  checkbox и строки; после исправления размеры 16×16, текст читаем,
  горизонтального переполнения списка нет.
