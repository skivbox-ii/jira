# Быстродействие «Динамики»: результат

## Статус

PERF-01 реализован и проверен локально. Прод-приёмка не завершена:
Citrix показывает `Failed to reconnect`. Пункт не закрывать до личного
read-only прогона в восстановленной сессии Jira.
Исходная версия `0fb73a2`, ветка `codex/import-registry-details`.

## Изменения И Границы

- `activity-loader.js`: одна очередь, до трёх активных чтений, дедупликация,
  замена очереди при выборе дня, отмена jqXHR при возможности. Поздние
  ответы отменённой области/ненужного чтения не меняют данные отчёта.
  Неотменяемые чтения той же области занимают слот до завершения;
  после смены области могут физически завершиться, но результат отброшен.
- `main.js`: интеграция очереди; отдельный прогресс с объединением частых
  обновлений в интервале 100 мс. Таймер очищается при завершении/отмене.
- `activity-ui.js` и `rendering.js`: обновляется только блок прогресса,
  таблица, фокус и черновик фильтра не пересоздаются. Видны число прочитанных
  задач, активные ключи, очередь, ошибки и предупреждение о прежнем срезе.
  По окончании загрузки публикуется новый отчёт. Синхронное завершение при
  смене даты не запускает второй draw той же таблицы.
- `activity-store.js`: LRU до шести вычисленных отчётов. Консервативная
  граница версии данных: каждый основной render очищает кеш. Поэтому
  новый Excel, пользователь, область, команды, связи и снимки не используют
  старые результаты. Даты/компоненты внутри опубликованного набора используют
  кеш; переход полуночи МСК тоже его очищает. Фильтры колонок остаются
  фильтрами журнала и не меняют глобальные итоги.
- `activity-ai-ui.js`: дорогая подготовка контекста только при открытии
  окна; открытый/выполняющийся сеанс по-прежнему проверяет смену среза.
  Смена области отменяет старый разговор даже при закрытом окне.
  Полночь после выбранного дня подписана `24:00 МСК`.

Истории остаются в существующих снимках задач: второе хранилище исходных
данных не создавалось. Индексы доменного расчёта не добавлены: измеренный
расчёт 23–32 мс, основной лишний расход был в AI-подготовке. Не изменялись
проверка полноты, доменные метрики, API Jira, лимит исходных историй,
провайдер/настройки LLM, создание задач или синхронизации.
Нет нового сервера, БД, IndexedDB, фреймворка, worker или виртуализации.
