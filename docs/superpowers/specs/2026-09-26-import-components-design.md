# Компоненты и читаемая динамика

Подтверждено пользователем 26.09: реализовать автономно, выполнить личную
проверку Citrix, независимое ревью и второй цикл исправлений/проверки.

## Синхронизация

Отдельная команда Excel обновляет только компоненты исходных историй по
существующему moduleComponentMap и справочнику текущего проекта. Страница
подтверждения показывает ключ, исходный модуль, полный текущий и новый набор,
выбор строк (допустимые выбраны), общий чекбокс и результат каждой строки.
Компоненты заменяются на явно показанное соответствие, пустые/неизвестные
значения не очищают Jira. Дети, сроки и ответственные не изменяются.
Перед записью повторно читать задачу: если компоненты изменились после
просмотра, показывать конфликт без PUT. Запрос меняет только components по ID.
Дубликаты с противоречивым модулем блокируются, неизвестные результаты записи
не повторяются автоматически. Контекст проекта/файла/сопоставлений нельзя
менять во время записи. Реальные записи в Citrix агент не подтверждает.

## Общий срез динамики

Компоненты исходной истории определяют принадлежность замечания. Несколько
компонентов объединяются по OR, замечание в сводке считается один раз.
Отдельное значение «Без компонента», неизвестное поле не приравнивать к пустому.
Срез меняет метрики, переходы, сводки, журнал, экспорт и контекст LLM; фильтры
колонок журнала остаются локальными. Попап с поиском, стабильными чекбоксами,
командой «Только», Применить/Отмена/Сброс и сохранением на пользователя/проект.
У компонента число подтверждённо открытых замечаний на выбранный срез,
неизвестные состояния показываются отдельно, без предположения о закрытии.
Принадлежность компоненту текущая, исторический компонент не выдумывается.

Экранная форма: показывать только явное значение поля «Экранная форма» или
«Привязка к экранной форме» из журнала/сохранённой импортной таблицы Jira.
Не извлекать предположения из темы и не подменять форму компонентом.
Если данных нет, не создавать ложную привязку. Это консервативное решение
для неуточнённой части запроса, не препятствующее остальной реализации.

## Журнал и производительность

Одна задача, один автор и минута остаются группой. Сразу видны краткие
формулировки каждого действия, а не только число изменений. Подробности
показывают автора, время, исполнителя и значения до/после. Выполнение зелёное.
Не менять исходные события и расчёты. Раскрытие группы не пересчитывает отчёт
и не пересоздаёт соседние строки. Сохранять прокрутку, фокус и фильтры.

## Приёмка

TDD для новых контрактов, полный existing suite, независимое ревью с циклом
исправления, локальные desktop/mobile и большой синтетический срез. Затем
commit-pinned публикация, сверка CDN и личная read-only проверка Citrix:
предпросмотр синхронизации (без подтверждения), фильтры, сводки, события,
прокрутка до конца и повторный просмотр после исправлений. Итоги и ограничения
фиксировать в отчёте, не объявлять проверку записи на проде выполненной.
