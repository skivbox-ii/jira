# Диагностика LLM-запросов импортера

Статус: подтверждено пользователем «Да, делай полную диагностику», 27.09.2026.

## Установленные факты

- В Citrix у замечания #2655 ошибка генерации видна после успешного чтения
  двух задач и подготовки контекста. Повторный запрос агент не запускал.
- `main.js:onActivityLlmRequest` заменяет все ошибки транспорта общей
  фразой. Из неё нельзя установить HTTP-код или причину отказа провайдера.
- Общий `llm-client.js` читает ответ через `resp.text()`, разбирает JSON
  и извлекает текст, но не сохраняет этап, время, заголовки или usage.
- Прежняя приёмка AI-04 проверяла подготовку запроса, а не рабочую генерацию.

## Выбор решения

Рекомендуется общий безопасный trace транспорта и отдельная панель
в отчётах импортера. Альтернатива только с коротким текстом ошибки
не отвечает запросу о содержимом и таймингах. Журнал только в консоли
неудобен в Citrix и повышает риск случайного раскрытия секретов.

## Пользовательский сценарий

- Ошибка содержит конкретный наблюдаемый этап и ссылку «Диагностика запроса».
- Панель открывается поверх отчёта, не теряет его контекст и закрывается
  с возвратом фокуса. Длинные запросы/ответы доступны с прокруткой.
- Разделы: итог, запрос, хронология, ответ, ограничения наблюдения.
- Доступна явная выгрузка очищенной диагностики в JSON. Предупреждение:
  файл может содержать тексты замечаний и персональные данные участников.
- Один и тот же механизм работает в разборе замечания, общем отчёте
  и вопросах по отчёту. Ошибка старого запроса не относится к новому запуску.
- Trace хранится только в памяти текущего отчёта, не в localStorage,
  консоли, телеметрии или репозитории. Никаких фоновых запросов.

## Содержание trace

- Локальный ID попытки, начало/конец с часовым поясом, длительность.
- Фактический URL без секретов, метод, модель, протокол chat/completions
  или completions, режим credentials и разрешённые заголовки запроса.
- Реальное сериализованное тело после подготовки клиентом, отдельно
  исходный размер тела и промптов в UTF-8 байтах. Редакция секретов явно
  обозначена; очищенное представление не выдаётся за побайтовый дамп сети.
- Этапы: подготовка, вызов fetch, получение HTTP-заголовков, чтение тела,
  разбор JSON, извлечение ответа. Для каждого доступные время и результат.
- Различать отказ до получения HTTP-ответа, HTTP 4xx/5xx, ошибку чтения
  тела, неверный JSON, пустой/неподдерживаемый ответ. Сохранять исходный
  наблюдаемый класс ошибки с безопасным текстом, не заменять диагнозом.
- Статус, доступные заголовки ответа, MIME, размер прочитанного тела,
  очищенное содержимое, структура JSON, finish_reason, request ID и usage
  при наличии. Ограничение размера диагностического отображения явно
  показывается вместе с размером полного прочитанного тела.
- Токены: только фактические числовые поля usage провайдера с источником.
  При отсутствии usage писать «неизвестно», не пересчитывать байты в токены
  и не считать локальный размер доказательством приёма запроса сервером.

## Безопасность и пределы наблюдения

- Ключ API, Authorization, cookies, токены в URL и отражённые секреты
  очищаются до передачи trace в UI, экспорта или помещения в ошибку.
- Значения неизвестных потенциально секретных заголовков не раскрывать;
  имена и факт скрытия показывать. HTML ответа отображать только текстом.
- Не читать document.cookie. Список реально отправленных Cookie и
  Set-Cookie недоступен обычному коду страницы; не выдумывать их отсутствие.
- DNS/TCP/TLS доступны только при наличии разрешённых Resource Timing
  данных с надёжной привязкой к запросу. Иначе «браузер не предоставил».
- Fetch не сообщает причину закрытия сокета; ошибка до HTTP-ответа
  не доказывает отдельно CORS, DNS, TLS или обрыв соединения.
- Не менять endpoint, авторизацию, payload, credentials, лимиты или
  fallback-политику ради диагностики. Не добавлять автоматических повторов.
- В общем клиенте диагностика включается для вызовов отчётов явно;
  существующие потребители других виджетов сохраняют свой контракт.

## Проверки и приёмка

- RED/GREEN: отклонённый fetch, синхронное исключение, HTTP 401/403/429/500,
  отказ чтения тела, HTML вместо JSON, битый JSON, пустой ответ, валидный
  JSON неизвестной структуры, успешный ответ с usage и без usage.
- Проверить отсутствие секретов в ошибке, trace, DOM и экспорте, включая
  отражение ключа провайдером и секреты в URL; ответ с HTML не исполняется.
- Контекст диагностики соответствует реально отправленному телу; этапы
  и длительность не приписываются другим одновременным запросам.
- Один явный вызов, без fallback для однозапросных отчётов; никаких новых
  запросов при открытии/экспорте trace. Частичный отчёт не теряется.
- Desktop/mobile: прокрутка до конца, возврат к отчёту, клавиатура,
  повтор после ошибки, смена среза, закрытие во время запроса.
- Независимое ревью и регрессии существующего клиента/отчётов обязательны.
- Citrix: только read-only действия. Живую генерацию запускает пользователь;
  агент не выдаёт локальную заглушку за подтверждённую причину прод-сбоя.
