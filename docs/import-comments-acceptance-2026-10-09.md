# ACT-07: комментарии в Динамике

## Объём

Запрос 09.10: добавить отсутствующие комментарии в дневной журнал,
показать до трёх строк и «…» при переполнении, полный текст открывать
по наведению, нажатию и с клавиатуры. Группировка не меняется.

Причина воспроизведена на заглушке: комментарий присутствовал в снимке
Jira и данных управленческого отчёта, но дневные события строились
только по changelog и созданию задачи. Результат: 0 событий вместо 1.

## Изменения

- `activity.js`: события добавления и последнего известного редактирования,
  автор, тикет, время МСК, исполнитель на время события, точный текст.
  Общий ребёнок не удваивает глобальные события. Подтверждённые дубликаты
  changelog убираются; неоднозначные записи неполного списка сохраняются.
- `activity-loader.js`, `main.js`: дочитывание доступных страниц с прежним
  ограничением конкурентности, отменой и явным повтором после ошибки.
  Проверяются смещения, ID, число комментариев и изменение списка.
  На ошибке сохраняется объединение уже полученных текстов; противоречивое
  общее число становится неизвестным. Время снимка истории фиксируется
  до чтения дополнительных страниц, а не после них.
- `activity-ui.js`, CSS: три строки, одна кнопка «…» в третьей строке,
  попап с точным текстом и переносами, прокруткой и доступным закрытием.
  Короткому тексту кнопка не добавляется. HTML из комментария не исполняется.
- `activity-ai.js`: отдельная полнота комментариев передаётся в существующий
  контекст отчёта; никакого живого LLM-вызова при проверках.
- Полный HTML-экспорт сохраняет текст без визуального ограничения.
  Локальные заглушки явно описывают пустые списки комментариев; JSDOM
  получает отсутствующий в нём `structuredClone` из Node для Mermaid.

## Ограничения

Удалённые комментарии и промежуточные редакции Jira не восстанавливаются.
При поздней правке показанный текущий текст явно помечен. Полнота списка
комментариев не означает полноту всей исторической переписки.

Production-приёмка комментариев не завершена, ACT-07 не закрыта.
Следующий шаг: личная read-only сверка существующего комментария с дневным
журналом в Citrix; не создавать комментарии и не менять тикеты ради проверки.
