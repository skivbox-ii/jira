# Приёмка диагностики LLM, 27.09.2026

## Объём и причина

Пользователь подтвердил полную диагностику LLM-отчётов. На снимке Citrix
18:53 МСК у #2655 видна общая ошибка после подготовки полного контекста.
Причина потери деталей установлена: `onActivityLlmRequest` заменял любой
отказ общей фразой. Причина отказа рабочего LLM этим не установлена.

Доказательство исходного состояния:
`~/.codex/citrix-prod-runs/import-llm-trace-20260927/screenshots/inspect-20260927-185317-01775.png`.
Страницу при исследовании не обновлял, генерацию не повторял.

## Реализация

- Опциональный trace общего клиента: фактический URL и JSON запроса,
  модель, размер UTF-8, начало/конец, этапы и длительность, HTTP-статус,
  доступные безопасные заголовки, тело/структура ответа и usage.
- Ошибки подготовки, получения HTTP-ответа, чтения тела, HTTP, JSON
  и извлечения текста различаются. HTTP-отказ не означает обрыв тела.
- Токены без usage остаются неизвестными. Cookie и причина закрытия
  сокета не выдумываются. Сетевые тайминги отображаются лишь при доступных
  браузерных данных; отказ до HTTP не доказывает приём сервером.
- Ключи и распознанные секретные поля очищаются до callback. Проверены
  отражённые секреты, вложенный JSON, URL userinfo/query/fragment/path,
  lower-case и повторное percent-encoding. Не утверждается, что возможна
  автоматическая идентификация всех секретов в произвольном тексте Jira.
- Единая панель для разбора замечания, общего отчёта и вопросов:
  русские метки, МСК, этапы, раскрываемые форматированные JSON-тела,
  переносы, прокрутка и явная выгрузка. HTML ответа не исполняется.
- До десяти попыток текущего запуска в памяти, пропуски явно указаны.
  Нет localStorage/console/телеметрии, фоновых запросов и новых повторов.
  Диагностика добавляется только при подписке отчёта; остальные вызовы
  общего клиента не собирают trace.
- Закрытие общего отчёта сохраняет существующий активный запрос:
  повторное открытие не разрешает вторую отправку до его окончания,
  а итоговый trace сохраняется и при закрытом окне. Смена среза изолирована.

Ручные исходники: общий `llm-client.js`, importer `main.js`,
`llm-diagnostics-ui.js`, два report UI, узкий CSS и порядок сборки.
Общий клиент также встроен в Timesheet и User Activity, поэтому их
производные JS/runtime синхронизированы механической сборкой.
Ручные модули этих виджетов, bootstrap/release metadata не менялись.

## Ограничение приёмки

Полная регрессия завершена; публикация и прод-приёмка фиксируются ниже.
Живой LLM-запрос по-прежнему запускает пользователь. Новый trace конкретной
производственной ошибки ещё не получен; её причина и исправление отказа
провайдера не заявлены. Проверка подготовки запроса не равна проверке
успешного рабочего ответа.
