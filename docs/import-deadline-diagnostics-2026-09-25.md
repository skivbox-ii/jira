# DUE-02: диагностика сроков

## Объём

Пункт продолжает разбор 39 нераспознанных сроков из прод-приёмки DUE-01.
Диагностика должна раскрывать номер замечания, ссылку Jira, реальный заголовок
поля, исходное значение и источник: загруженный Excel либо сохранённая таблица
из описания исходной истории Jira. При конфликте нужны все значения.

В существующей строке покрытия сроками появляется команда «Ошибки сроков»:
наведение/фокус раскрывает полный прокручиваемый список, клик открывает полную
сводку. Доступ нужен и из сводки просрочки. Это не новая строка фильтров и не
седьмой верхний показатель. Ошибки сроков не зависят от выбранного дня событий
или фильтра журнала; замечания без событий не исключаются.

## Ограничения данных

- Правила принятия дат и приоритет Excel не расширяются. Неоднозначную дату
  нельзя угадывать или автоматически считать просроченной.
- Причины различаются: неподдерживаемый/неоднозначный формат, невозможная
  календарная дата, противоречивые значения. Отсутствие срока отдельно от ошибки.
- Исходный текст отображается безопасно, без исполнения HTML.
- Все сведения берутся из уже загруженного среза; открытие сводки не читает
  Jira повторно, не изменяет тикеты и не вызывает LLM.
- Неполное покрытие сроками оставляет число просроченных нижней границей.
- Сведения сохраняются в существующих HTML-экспорте и контексте LLM.

производственный код сравнивает сроки с реальной текущей датой МСК.
