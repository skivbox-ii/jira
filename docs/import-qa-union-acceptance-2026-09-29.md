# REG-06: уточнение составного фильтра QA

## Объём

Запрос 29.09: тестировать и сразу внедрить ИЛИ из трёх условий:
точный статус тестирования, роль QA с любым статусом, исполнитель из
настроенной команды QA. Учитываются исходные истории и дочерние задачи.
Другие выбранные фильтры пересекаются с этим результатом; они не сбрасываются.

## Причина и изменения

- `teams.js`: прежний ранний возврат QA игнорировал участников и отсекал
  завершённые/неизвестные статусы. Теперь используется объединение трёх
  независимых условий, без изменения `currentWork` и других команд.
- `main.js`: независимое ревью обнаружило потерю `assigneeIdentifiers`
  у только что созданного ребёнка. Сохраняются известные идентификаторы
  существующим `userIdentifiers`; имя само по себе не доказывает членство.
- Обе сборки, unit/grid-тесты, локальный сценарий и контракт таблицы обновлены.
